# セキュリティ仕様書

認証・認可・入力バリデーション・データ保護方針を定義する。

**前提**: 本プロジェクトはローカル学習・検証用途であり、強固なセキュリティはスコープ外（[`01-business-requirements.md`](./01-business-requirements.md)）。本書はローカルでの最低限の方針と、**本番化（将来の Web アプリ統合）時の留意点**を併記する。

## 認証

- **task-app**: 認証なし（誰でもタスク操作可能）。example のため簡略化。
- **Grafana**: 管理者 1 ユーザー（既定 `admin` / `admin`）。資格情報は環境変数で設定。
- **OTLP（Collector 受信）**: 認証なし（Compose 内部ネットワークに閉じる）。

> 本番化時: task-app に認証（セッション/トークン）を導入。Grafana の既定パスワードを必ず変更。OTLP には mTLS / トークン認可を検討し、外部公開ポートを最小化する。

## 認可（権限制御）

- 現状ロールは持たない（全操作が同一権限）。
- API のバリデーション・404 判定は**サーバー側で実施**し、画面側の制御にのみ依存しない。

> 本番化時: タスクの所有者概念・ロール（閲覧/編集）を導入し、サーバー側で必ず権限チェックを行う。

## 入力バリデーション

UI と API の双方で実施する。最終的な正当性判断は API（サーバー側）が担う。

| フィールド | ルール |
|-----------|--------|
| title | 必須 / 前後トリム後 1 文字以上 / 空白のみ不可。違反は 400 |
| done | 真偽値のみ許可。型不一致は 400 |
| id（パスパラメータ） | UUID 形式。不正形式は 400、未存在は 404 |

- SQL は **パラメータ化クエリ**（`pg` のプレースホルダ）で発行し、文字列連結を禁止（SQLi 対策）。

## データ保護

- 業務データ（tasks）に個人情報・機密は含めない方針（example）。
- 秘匿情報（DB パスワード等）は `.env` 管理とし、リポジトリにコミットしない（`.gitignore`）。`.env.example` はダミー値のみ。
- テレメトリに機密値（資格情報・トークン等）を載せない。必要に応じ Collector の processor で属性を除去/マスクする。

> 本番化時: 保存データの暗号化・アクセス制御（DB ロール / RLS）・秘匿情報のシークレットマネージャ管理を検討。

## 脆弱性対策

| 脅威 | 対策 |
|------|------|
| SQL インジェクション | パラメータ化クエリの徹底（文字列連結禁止） |
| XSS | Vue のテンプレートエスケープに依拠。`v-html` を使わない |
| 機密漏えい | `.env` を Git 管理外に。テレメトリへ機密を出力しない |
| ポート露出 | 外部公開は必要なポートに限定（Compose 内部通信は非公開） |

> 本番化時: CSRF 対策（状態変更 API のトークン化）、依存パッケージの脆弱性スキャン、HTTPS 終端を追加する。
