# テストルール

## テスト分類

| 分類 | 定義 |
|------|------|
| 正常系（Normal） | 期待通りの入力 → 正しい結果 |
| 準正常系（Semi-Normal） | 想定内の異常入力 → 適切なハンドリング |
| 異常系（Abnormal） | 想定外のエラー → 安全な失敗 |

## 原則

- テストは仕様の証明。テストが失敗したら実装を修正する（テストを実装に合わせない）。
- 正常系 1 : 異常系（準正常系 + 異常系）2 以上の比率を目安とする。
- ビジネスロジックをモックしない。モックは外部 I/O（HTTP通信、DB接続、ファイルシステム）のみ。
- `toBeTruthy()` 等の曖昧なアサーションを避け、具体的な値で検証する。

## テストツール

| テスト種別 | ツール | 状態 |
|-----------|--------|------|
| ユニットテスト | Vitest（+ コンポーネントテストは Vue Test Utils） | 導入済み（`pnpm test`） |
| DB を伴うロジックテスト | pg-mem（インメモリ PostgreSQL） | 導入済み |
| E2E テスト | Playwright | 未導入（追加時は `e2e/` へ） |

## テストファイル配置

テストは**専用ディレクトリに集約する**（ソースにコロケートしない）:

- **ユニット / コンポーネントテスト**: `apps/task-app/tests/` に集約（例: `tests/tasks.test.ts`）
- **E2E テスト**: リポジトリ直下の `e2e/` に集約（例: `e2e/task-flow.spec.ts`）
- `pages/` `components/` `server/` などのソースツリーにテストファイルを置かない。

## DB を伴うテストの方針

- **pg-mem は「外部 I/O のモック」であり、ビジネスロジックのモックではない**。`Queryable` インターフェース越しに `pg.Pool` の代わりを注入し、**SQL を含めた実際の振る舞い**を検証する（`api.md`「外部 I/O は引数で受け取る」）。
- 検証対象の関数をスタブで置き換えない。バリデーション・エラー分岐は**実装をそのまま通して**確認する。
- テストごとにスキーマを初期化し、**テスト間で状態を共有しない**。

## テレメトリはテスト対象にしない

- OpenTelemetry の送出（スパン・メトリクス・ログ）はユニットテストの検証対象に含めない。Collector とバックエンドを含む結合動作であり、`docker compose up` 後の Grafana 上での目視確認で担保する（[`08-test-specification.md`](../../docs/08-test-specification.md)）。
- ただし**ログ出力がエラー処理の一部である場合**（例外を握り潰していないこと）は、ロジック側のエラー伝播テストで担保する。
