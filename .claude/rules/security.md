# セキュリティ

## 認証・認可

- 認証方式はプロジェクト要件に応じて選択する（JWT / セッション / Supabase Auth 等）。
- API エンドポイントごとにアクセス制御を設定する（公開 / 認証必須 / ロールベース）。

## 通信・アクセス制御

- 全通信は **HTTPS** を必須とする。
- **CORS** は許可するオリジンを明示的に指定する（`*` は本番で使用しない）。
- **レートリミット** を導入する（認証系エンドポイントは特に厳しく制限）。

## インジェクション対策

- **SQL インジェクション**: パラメータバインド（`pg` の `$1` プレースホルダ）を必須とする。**生 SQL の文字列結合は禁止**。動的に列を組み立てる場合も、値は必ずプレースホルダで渡す（実装例: [`server/utils/tasks.ts`](../../apps/task-app/server/utils/tasks.ts) の `updateTask`）。
- **XSS**: ユーザー入力のサニタイズ + CSP ヘッダー設定 + 出力エスケープの多層防御。Vue のテンプレート補間は自動エスケープされるが、`v-html` はこれを迂回するため原則使わない。
- **CSRF**: セッション認証の場合は CSRF トークン必須。Bearer Token 認証（Cookie に保存しない場合）は不要。

## シークレット管理

- ローカル環境: `.env`（`.gitignore` に追加必須）。値の雛形は `.env.example` にのみ置く。
- 本番環境: Secret Manager 等のマネージドサービスを使用。

## テレメトリに機密を載せない

監視スタックを持つ本プロジェクト固有の注意点。**テレメトリは第 2 のログ出力先であり、同じ機密の扱いが要求される**。

- スパン属性・メトリクスのラベル・ログ属性に、パスワード・トークン・個人情報を入れない。**Tempo / Loki / Prometheus に入った値は、Grafana を開ける全員が閲覧できる**。
- 自動計装は DB クエリやリクエストヘッダを属性として拾いうる。機密を含む可能性がある属性は Collector の processor で落とす。
- ログ出力は [`server/utils/logger.ts`](../../apps/task-app/server/utils/logger.ts) を経由し、属性に何を載せるかを明示的に選ぶ。オブジェクトを丸ごと渡さない（`sanitize` が JSON 文字列化するため、意図しないフィールドまで送出される）。
- Grafana の既定管理者資格情報（`admin` / `admin`）と、認証を持たない task-app・OTLP エンドポイントはローカル検証用の前提である。公開ネットワークへ露出させない（[`06-security-specification.md`](../../docs/06-security-specification.md)）。
